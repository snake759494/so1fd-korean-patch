# 이슈 #1: PSP-3000 실행 직후 종료

2026-09-28 기준 보고 내용은 PSP-3000 실기에서 구동 실패 후 홈 화면으로 돌아간다는 것입니다. 오류 번호, 커스텀 펌웨어 종류·버전, 원본 실행 여부는 아직 확인되지 않았습니다.

## 조사 및 수정 후보

Review 10의 이름 후크 빌드는 원본 ELF의 섹션 테이블 공간에 추가 코드를 넣고 섹션 헤더 정보를 제거했습니다. 프로그램 헤더도 파일 끝으로 이동했습니다. 이는 PPSSPP에서 실행됐지만 실기 로더와 동일한 호환성을 의미하지 않습니다.

ARK/PRO 계열의 `_ProbeExec2`는 정적 ELF의 모듈 정보를 보완할 때 섹션 이름 `.rodata.sceModuleInfo`를 검색합니다. Review 10에는 해당 검색에 필요한 섹션 정보가 없습니다. 따라서 실기 실행 실패와 관련될 수 있는 구체적인 호환성 문제를 확인했습니다. 다만 보고자의 펌웨어를 알 수 없고 PSP 실기 재현을 수행하지 않았으므로, 이것이 보고된 실패의 확정 원인이라고 단정하지 않습니다.

검토한 외부 소스: [ARK-4 loadercore.c, 고정 커밋](https://github.com/PSP-Archive/ARK-4/blob/7c03c3735503dc3fad999f4687b890fefef6467d/core/systemctrl/src/loadercore.c), [ELF 섹션 문자열 검색](https://github.com/PSP-Archive/ARK-4/blob/7c03c3735503dc3fad999f4687b890fefef6467d/core/systemctrl/src/elf.c). 해당 코드를 저장소에 복사하지 않았습니다.

Review 11 RC1은 다음과 같이 ELF를 다시 배치합니다.

- 프로그램 헤더 2개를 파일 앞부분의 오프셋 52에 배치합니다.
- 원본 섹션 24개와 섹션 문자열, 모듈 정보를 보존합니다.
- 데이터의 파일 오프셋과 모듈 정보 위치를 새 배치에 맞게 조정합니다.
- 이름 후크 코드를 원본 섹션 자료 뒤에 배치합니다.
- 게임이 메모리에 로드하는 두 세그먼트의 바이트와 가상주소는 Review 10과 동일하게 유지합니다.
- ISO의 BOOT/EBOOT 및 해당 디렉터리 크기 필드만 변경합니다. 기존에 배정된 섹터 내의 빈 공간만 사용하고, 모든 번역·영상·글꼴 자원은 그대로 유지합니다.

`work/full_patch/build_review11.py`는 검증된 원본 ISO와 Review 10 ISO를 입력으로 사용하며 원본부터 적용하는 새로운 xdelta를 생성합니다. 원본이나 중간 ISO는 배포하지 않습니다.

## 해결 여부

정적 구조 검사와 PPSSPP 부팅은 실기 구동 성공을 대신할 수 없습니다. **이슈 #1은 실기 확인 대기 상태이며 아직 닫지 않습니다.** RC1은 시험판으로 공개하고 Review 10 정식 릴리즈를 대체하지 않습니다.

확인에 필요한 정보는 PSP 모델, 커스텀 펌웨어 이름·버전, 오류 번호, 원본 일본판 실행 여부 및 RC1 결과입니다. 이전 스테이트를 사용하지 말고 원본 ISO에 RC1을 적용한 뒤 게임을 새로 실행해 주세요. 부팅 성공뿐 아니라 새 게임의 한글 이름 화면과 게임 진입도 확인이 필요합니다.
